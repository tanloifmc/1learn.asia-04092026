# 10 REPORT DATA CONTRACT SPECIFICATION

## 1. Contract Purpose
The `ReportData` contract (defined in `src/types/report.ts`) is the single, deterministic interface between the Backend Interpretation/Report Engine and the Report UI. The UI must only read this data and must not compute, interpret, or guess business logic.

## 2. Global Structure
The contract organizes data by capability, ensuring strict typing and avoiding implicit "any" structures.
```text
ReportData
├── assessmentId, userId, generatedAt
├── validity (GlobalValidity)
├── identity (IdentityCapability)
├── riasec (RiasecCapability)
├── bigFive (BigFiveCapability)
├── workValues (WorkValuesCapability)
├── strengths, watchOuts, environments (InterpretationCapability)
├── crossDimension (PatternsCapability)
├── careerExploration, majorExploration, universityExploration, actionPlan (FutureExplorationCapability)
└── executiveSnapshot (NarrativeCapability)
```

## 3. Validity
`GlobalValidity` enum strictly supports: `VALID`, `QUESTIONABLE`, `INVALID`, `UNDETERMINED`.
The UI uses this to determine if the report is rendered, warned, or blocked. No fallback to `VALID` is allowed.

## 4. Capability Availability & Access State
The `CapabilityState` has been broken down to avoid confusing global access with data presence:
- `CapabilityAvailability` tracks if the engine has data: `AVAILABLE | EMPTY | NOT_AVAILABLE | ERROR`.
- `AccessState` tracks user rights: `FREE | PREMIUM | PREMIUM_LOCKED`.
The UI uses `availability` to determine how to render a section and `access` to determine if a Premium Teaser should be displayed. Future engines are explicitly set to `availability: 'NOT_AVAILABLE'`.

## 5. Free / Premium Boundary
The data contract schema is canonical. The engine controls what is populated in the fields based on user access. The UI uses the `state` (e.g., `PREMIUM_LOCKED`) to determine if a Premium Teaser should be displayed. Future engines are explicitly set to `NOT_AVAILABLE`.

## 6. RIASEC
Contains `RiasecCapability` which provides `dimensions`, `primary`, `secondary`, and `hollandCode`. Ranks and normalizations are computed by the engine.

## 7. Big Five
Contains `BigFiveCapability`. The classification (`PROMINENT`, `MODERATE`, `LOWER`) is provided by the engine. UI does no mean calculations or thresholding.

## 8. Work Values
Contains `WorkValuesCapability`. Top 3/6 ranking is explicitly provided by the engine. UI does no tie-breaking.

## 9. Cross-Dimension
Contains `PatternsCapability`. If no patterns exist, `patterns: []`. AI is prohibited from generating patterns dynamically.

## 10. Strengths
Contains `InterpretationCapability`. Strengths mapped from engine rules, providing `evidence` and `implication`.

## 11. Watch-outs
Contains `InterpretationCapability`. Same structure as strengths. UI does not invent watch-outs or use the word "weakness".

## 12. Environment
Contains `InterpretationCapability`. Environments generated by rules engine.

## 13. Future Engines
Careers, Majors, Universities, and Roadmap use `FutureExplorationCapability<never>` for this phase. The UI must recognize `NOT_AVAILABLE`.

## 14. AI Narrative Boundary
The AI writer can only produce the `executiveSnapshot.aiNarrative` as an optional presentation layer based on pre-approved rules and `deterministicSummary`. The AI is NOT a dependency for a valid ReportData. The AI cannot mutate any other capability in the `ReportData`.

## 15. Forbidden Behaviors
- Mocking data for future engines.
- Using `any` or loose typing.
- Computing scores or interpreting rules in the UI.
- Falling back `UNDETERMINED` validity to `VALID`.

## 16. Example VALID payload
```json
{
  "validity": "VALID",
  "identity": { "state": "AVAILABLE", "title": "Người Khám Phá Hệ Thống", "explanation": "..." },
  "riasec": { "state": "AVAILABLE", "dimensions": [...], "primary": "I", "secondary": "R", "hollandCode": "IRC", "interpretation": "..." },
  "careerExploration": { "state": "NOT_AVAILABLE", "data": [] }
}
```

## 17. Example QUESTIONABLE payload
```json
{
  "validity": "QUESTIONABLE",
  "identity": { "state": "AVAILABLE", ... }
}
```

## 18. Example UNDETERMINED payload
```json
{
  "validity": "UNDETERMINED",
  "identity": { "state": "EMPTY", "title": null, "explanation": null }
}
```

## 19. Example NOT_AVAILABLE future capability
```json
{
  "careerExploration": {
    "state": "NOT_AVAILABLE",
    "data": []
  }
}
```
